~~删除线~~├─ 【系统组成层・整体包含关系】
│  └─ DBS 数据库系统（最大范畴）
│     ├─ DB 数据库：长期存储在计算机内、有组织的结构化数据集合
│     │  └─ 数据库对象
│     │     ├─ 表：真正持久存储原始数据；例：student(学号,姓名)
│     │     ├─ 视图：虚拟表，仅保存查询语句，不存储数据；例：只展示学生学号、姓名，隐藏年龄
│     │     ├─ 存储过程：预编译SQL集合，手动调用；例：传入学号查询该学生所有选课成绩
│     │     └─ 触发器：绑定数据表，增删改时自动执行；例：删除学生时自动删除对应的选课记录
│     ├─ DBMS 数据库管理系统：核心系统软件（MySQL、Oracle、Neo4j）；负责统一管理、控制数据库，提供数据存取、事务、完整性、安全性、故障恢复等核心能力
│     │  ├─ DBMS 四大核心保障特性（所有 DBMS 通用目标）
│     │  │  ├─ 可靠性：保障数据不丢失、系统故障可恢复（作用于底层持久化数据，即基础表存储内容）
│     │  │  ├─ 一致性：保障事务执行前后业务数据逻辑合法（作用于事务操作流程）
│     │  │  ├─ 完整性：保障数据取值、关联关系合规有效（约束仅定义在基础数据表，视图等衍生对象无独立约束）
│     │  │  └─ 安全性：保障数据访问权限可控、防越权篡改（可管控全部数据库对象：表、视图、存储过程、触发器）
│     │  └─ DBMS 通用三级模式架构（所有 DBMS 统一架构，与数据模型无关）
│     │     ├─ 外模式（用户 / 子模式）：面向应用的局部逻辑视图，一个库可多个
│     │     ├─ 模式（逻辑模式）：数据库全局唯一逻辑结构
│     │     ├─ 内模式（存储模式）：数据库唯一物理存储结构
│     │     ├─ 外模式 / 模式映像：实现逻辑独立性
│     │     └─ 模式 / 内模式映像：实现物理独立性
│     ├─ 数据库开发工具（Navicat、DBeaver、数据库驱动）
│     ├─ 数据库应用系统（教务系统、电商后台、银行系统）
│     ├─ DBA 数据库管理员：运维、安全、调优人员
│     └─ 用户（普通终端用户、开发人员）
├─ 【数据模型分层・抽象度从高到低】
│  └─ 数据模型（总称，分三大层级）
│     ├─ 概念模型（信息模型）
│     │  ├─ 定位：面向业务语义，与具体 DBMS 无关
│     │  └─ 典型代表：E-R / ERD 实体-联系模型/E-R图
│     │     ├─ 核心元素：实体、实体型、实体集、属性、联系
│     │     └─ 实体码：概念层的唯一标识
│     ├─ 逻辑数据模型
│     │  ├─ 定位：面向数据库逻辑结构，独立于物理存储
│     │  ├─ 经典传统模型
│     │  │  ├─ 层次模型（早期，如 IMS）
│     │  │  ├─ 网状模型（早期，DBTG 系统）
│     │  │  └─ 关系模型（学习核心，当前主流）
│     │  │     ├─ 代表产品：MySQL、Oracle、SQL Server、PostgreSQL
│     │  │     ├─ 基础结构：关系、关系模式、元组、属性、目/度
│     │  │     ├─ 码体系（从属包含关系）
│     │  │     │  └─ 码 / 关键字（统称）
│     │  │     │     ├─ CK 候选码：满足唯一性+最小性
│     │  │     │     │  └─ PK 主码 / 主键：从候选码中选定一个
│     │  │     │     ├─ FK 外码 / 外键：表间参照关联
│     │  │     │     └─ 全码：特殊候选码（全部属性组成）
│     │  │     ├─ 规范化理论
│     │  │     │  ├─ FD 函数依赖：属性间的决定关系
│     │  │     │  └─ NF 范式体系（严格子集：高范式⊂低范式）
│     │  │     │     ├─ 1NF 第一范式（关系准入门槛）
│     │  │     │     ├─ 2NF 第二范式 ⊂ 1NF
│     │  │     │     ├─ 3NF 第三范式 ⊂ 2NF
│     │  │     │     └─ BCNF 巴斯-科德范式 ⊂ 3NF
│     │  │     └─ 关系代数运算（封闭性：输入输出均为关系）
│     │  │        ├─ 四大类运算符
│     │  │        │  ├─ 集合运算符：∪(并)、∩(交)、−(差)、×(广义笛卡尔积)
│     │  │        │  ├─ 专门关系运算符：σ选择、π投影、⋈连接、÷除
│     │  │        │  ├─ 比较运算符：>、≥、<、≤、=、≠（条件判断辅助）
│     │  │        │  └─ 逻辑运算符：∧(与)、∨(或)、¬(非)（组合多个条件）
│     │  │        └─ 重要区分
│     │  │           ├─ 集合运算前提：参与运算关系结构一致（并相容性）
│     │  │           ├─ θ连接 = 笛卡尔积 + 选择；自然连接 = 笛卡尔积+选择+投影
│     │  │           └─ 比较、逻辑运算符仅用于构造筛选条件，不能独立运算
│     │  └─ NoSQL 现代逻辑模型（非关系模型）
│     │     ├─ 键值模型（Redis）
│     │     ├─ 文档模型（MongoDB）
│     │     ├─ 列簇模型（HBase）
│     │     └─ 图模型（Neo4j）
│     └─ 物理数据模型
│        ├─ 定位：面向底层磁盘存储，与 DBMS / 硬件强相关
│        ├─ 核心内容：存储引擎、索引结构、数据文件、存取路径
│        └─ 典型技术：B+树索引、聚簇索引、页/块存储
├─ 【SQL 语言分类・并列从属关系】
│  └─ SQL 语言体系（RDBMS 的标准操作语言）
│     ├─ DDL 数据定义语言：CREATE / ALTER / DROP / TRUNCATE
│     ├─ DML 数据操纵语言：INSERT / UPDATE / DELETE
│     ├─ DQL 数据查询语言：SELECT
│     ├─ DCL 数据控制语言：GRANT / REVOKE
│     └─ TCL 事务控制语言：COMMIT / ROLLBACK / SAVEPOINT

└─ 【数据库全开发生命周期・全局闭环流程】
   ├─ 1.需求分析：梳理业务数据、功能、约束需求
   ├─ 2.数据模型设计阶段
   │  ├─ 2.1 概念结构设计：依托业务，构建 E-R 概念模型
   │  ├─ 2.2 逻辑结构设计：选定逻辑数据模型，设计表结构、范式、约束
   │  └─ 2.3 物理结构设计：依托物理模型，设计索引、存储、存取方案
   ├─ 3.数据库实施：建库建表、创建视图/存储过程/触发器、导入数据
   ├─ 4.系统运行架构生成：DBMS 自动生成三级模式架构、保障数据独立性
   ├─ 5.应用开发：基于 DBMS 开发上层业务应用系统
   └─ 6.运维迭代：性能调优、备份恢复、权限管理、需求迭代优化
