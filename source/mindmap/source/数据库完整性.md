- 数据库系统 - 数据库完整性
- 1. 完整性基础概念
  - 定义：数据的正确性、相容性，防止不合语义数据入库
  - 完整性控制三大机制
    - 定义功能：预先定义约束条件，存入数据库模式
    - 检查功能：执行操作时校验是否违反约束
    - 违约反应：拒绝操作 / 级联处理 / 置空等
  - 约束作用对象：列（属性）、元组（行）、关系（表），本质是对表以及表内行列数据设置约束规则
  - 约束时间分类【动静划分】
    - 静态约束：数据库静止状态下，数据必须永久满足的条件（考试绝大多数考点）
    - 动态约束：数据【修改前后】新旧数据必须满足条件
      - 举例：员工工资只能上涨、学生年级不能倒退
- ★2. 静态约束细分【按作用对象划分｜与三大完整性为两套独立分类】
  - 静态列级约束（单字段约束）
    - 数据类型、长度、精度
    - 取值范围、集合限制
    - 空值约束
    - 默认值、格式约束
  - 静态元组约束（同一行多字段约束）
    - 例：发货量 ≤ 订货量、归还日期＞借阅日期
  - 静态关系约束（表级/跨表约束｜内含三大完整性核心）
    - ①实体完整性【别称：行完整性】
      - 规则：基本关系【主属性】不能取空值
      - 实现：PRIMARY KEY 主键约束
      - 作用：唯一标识每一条元组（行）
      - 特点：主键唯一、非空、一张表最多一个主键
    - ②参照完整性【别称：引用完整性】
      - 实现：FOREIGN KEY 外键约束
      - 规则：外键值 = 主表主键有效值 OR NULL
      - 要求：主外键数据类型必须完全一致，字段名称可不同
      - 术语：从表=参照关系、主表=被参照关系
      - 违约三策略
        - 受限(RESTRICT)：有引用则禁止删改主表（默认）
        - 级联(CASCADE)：主表改动，从表同步改动
        - 置空(SET NULL)：主表删除，从表外键置空
    - ③用户自定义完整性
      - 定位：业务自定义规则，补全实体、参照之外的所有约束
      - 实现：CHECK、UNIQUE、NOT NULL、DEFAULT
      - 考试细分：域完整性【别称：列完整性】（用户自定义子集）
        - 作用：保证给定字段数据有效性，要求列数据具备正确的数据类型、格式、长度、有效取值范围
        - 考题固定结论：保证列取值范围正确 → 域完整性
- 3. 约束层级分类【考试超级重点｜属性约束 VS 表级约束】
  - 3.1 属性（列级）约束【只约束单个字段｜考题：定义属性上的约束条件】
    - NOT NULL：字段禁止为空
    - DEFAULT：字段未赋值时自动填充默认值
    - UNIQUE：字段值唯一，允许多个NULL
    - 列级CHECK：限制单列取值范围（年龄、性别）
- │  │
  - 3.2 表级约束【不属于属性约束｜可多字段、跨表】
    - PRIMARY KEY 主键：支持复合主键，不属于单属性约束
    - FOREIGN KEY 外键：跨两表约束，绝对不属于属性约束
    - 多字段联合UNIQUE
    - 元组级多字段CHECK约束
- │
- ★4. 六大SQL约束总对比（考试必背）
  - PRIMARY KEY：实体完整性【行完整性】、唯一且非空、表级约束
  - FOREIGN KEY：参照完整性【引用完整性】、跨表引用、表级约束
  - UNIQUE：唯一可空、属性级约束
  - NOT NULL：禁止空值、属性级约束
  - CHECK：范围限制、列级/元组级
  - DEFAULT：默认填充、属性级约束
- │
  - ✍综合代码示例（覆盖全部6类约束）
- │     -- Student表演示：PRIMARY KEY、UNIQUE、NOT NULL、DEFAULT、CHECK
- │     CREATE TABLE Student(
- │         Sno CHAR(9) PRIMARY KEY,        -- 主键约束
- │         Idcard CHAR(18) UNIQUE,          -- 唯一约束
- │         Sname CHAR(20) NOT NULL,         -- 非空约束
- │         Ssex CHAR(2) DEFAULT '男',       -- 默认值约束
- │         Sage INT CHECK(Sage BETWEEN 15 AND 45) -- 检查约束
- │     );
- │     -- SC表补充演示 FOREIGN KEY 外键约束
- │     CREATE TABLE SC(
- │         Sno CHAR(9),
- │         Cno CHAR(4),
- │         Grade INT,
- │         PRIMARY KEY(Sno,Cno),
- │         FOREIGN KEY(Sno) REFERENCES Student(Sno) -- 外键约束
- │     );
- │
- 5. 实体联系（E-R图/考题俗称：关系图）
  - 5.1 E-R图图形符号
    - 矩形：实体（学生、班级）
    - 椭圆形：属性
    - 菱形：实体之间的联系
    - 连线标注联系类型：1:1、1:n、m:n
  - 5.2 重要考点：联系【可以拥有自身属性】
    - 示例：学生与课程(m:n)选课联系，属性：成绩
  - 5.3 E-R图转关系模式建表规则
    - 5.3.1 一对一联系（1:1）
      - 规范实现：两张表关联字段均设为主键，互相作为外键
    - 5.3.2 一对多联系（1:n）【最高频】
      - 在多方建立外键，引用一方主键；多方字段不需要为主键
    - 5.3.3 多对多联系（m:n）
      - ❌禁止直接两表建立主外键、禁止合并为一张表
      - ✅必须新建中间关联表，存放双方主键构成联合主键
  - 5.4 拓展：允许表和自身建立联系（自引用/自联系，例如员工表上级引用员工号）
- │
- 6. 易混淆终极区分（选择判断绝杀）
  - 完整性=数据正确合规｜安全性=防止非法篡改窃取
  - 域完整性【列完整性】=单列范围｜参照完整性【引用完整性】=表间引用
  - 静态=状态合法｜动态=修改过程合法
  - 属性约束≠主键、外键（主外键都是表级）
  - 主外键：类型必须一致、名称可以不同
  - E-R图考点：联系可以带有属性；m:n必须新建中间表
  - 数据一致性：满足全部完整性约束，不只是数据类型一致
- 7. ★高频错题陷阱（重点标记）
  - 年龄范围限制 → 域完整性【列完整性】/用户自定义（非参照）
  - 主键不能空、UNIQUE可以空
  - 主外键类型必须完全一致，不是"差不多像就行"
  - 多对多不能合并为单张表，必须拆第三张表
  - 属性约束不包含PRIMARY KEY、FOREIGN KEY
  - 误区：联系不能拥有属性（❌错误）
  - 实体完整性【行完整性】：约束表中每一行记录
  - 域完整性【列完整性】：约束字段内数据取值
  - ★误区：数据一致性指数据类型一致性（❌错误，一致性包含全部完整性约束）
  - ★误区：不能在表与其自身之间创建联系（❌错误，支持自联系/自引用）
  - ★误区：数据完整性只能依靠约束实现（❌错误，约束、规则、事务、触发器均可实现）
  - ★主外键选择题提醒：正确仅有【名称可以不同】，部分劣质题库答案存在错误（切勿盲从题库）
  - ★实体完整性规则仅针对基本关系（基表），不适用于视图（视图不保存真实元组）

      if(!token || !token.startsWith('ghp_')&&!token.startsWith('github_pat_')){
        showPwdDialog('密码错误，请重试'); return;
      }
    } else if(pwdOrToken && pwdOrToken.length >= 30) {
      token = pwdOrToken;
      setToken(token);
    } else {
      token = getToken();
    }
    if(!token){showPwdDialog('');return;}
    var btn=document.getElementById('save-btn');
    var status=document.getElementById('save-status');
    btn.disabled=true;status.textContent='⏳ 保存中...';status.className='mindmap-save-status';
    var content=document.getElementById('mindmap-textarea').value;
    var path='source/raw_mindmap/'+sourceFilename;

    fetch('https://api.github.com/repos/'+owner+'/'+repo+'/contents/'+path,{
      headers:{Authorization:'Bearer '+token,Accept:'application/vnd.github+json'}
    }).then(function(r){
      if(!r.ok)throw new Error('获取文件信息失败 ('+r.status+')');
      return r.json();
    }).then(function(data){
      return fetch('https://api.github.com/repos/'+owner+'/'+repo+'/contents/'+path,{
        method:'PUT',
        headers:{Authorization:'Bearer '+token,'Content-Type':'application/json',Accept:'application/vnd.github+json'},
        body:JSON.stringify({message:'✏️ 更新 '+sourceFilename+' (via web editor)',content:utf8_to_b64(content),sha:data.sha})
      });
    }).then(function(r){
      if(!r.ok)throw new Error('提交失败 ('+r.status+')');
      status.textContent='✅ 已保存！GitHub Actions 正在重新部署，约1分钟后生效。';
      status.className='mindmap-save-status success';
      document.querySelector('#tree-view .mindmap-tree-text').textContent=content;
      btn.disabled=false;
    }).catch(function(err){
      status.textContent='❌ '+err.message;
      status.className='mindmap-save-status error';
      btn.disabled=false;
    });
  }
})();
</script>
