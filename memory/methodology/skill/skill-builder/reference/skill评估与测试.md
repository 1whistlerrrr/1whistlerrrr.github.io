# Skill 评估、测试与全生命周期规范
## 4. 评估与测试：确保 Skill 按预期工作
与传统软件测试类似，Skill 的评估需要覆盖不同层面，官方推荐三种测试方案：

| 测试类型 | 核心目标 | 方法示例 |
| ---- | ---- | ---- |
| **触发测试 (Triggering Tests)** | 确保 Skill 在正确时机加载，不会被无关查询误触发。<br>需构建测试用例集，包含**应触发、不应触发**两类用户查询。 | - 正向用例：`帮我规划一个冲刺` → 触发 `sprint-planning` skill<br>- 反向用例：`今天天气怎么样` → **不触发** `sprint-planning` skill |
| **功能测试 (Functional Tests)** | 验证 Skill 工作流输出正确性、API 调用成功率，妥善处理边界场景，保证结果一致性。 | 输入指定参数（如项目名称），断言 Skill 调用全部预期 API，并产出符合规范的结果。 |
| **性能对比 (Performance Comparison)** | 量化证明：使用 Skill 优于纯 Prompt / 人工操作。 | 设置基线指标（任务轮次、token 消耗、失败率），对比启用 Skill 前后的数据，体现价值。 |

### 实践技巧
Anthropic 推荐高效迭代思路：**不要一开始追求完整测试覆盖率**。
优先选取一个具备代表性、存在一定难度的任务，通过与 Agent 持续对话调试，直到任务稳定完美执行；再将这套成熟交互流程、解决方案提炼固化为 Skill。
在基础能力稳定后，扩充更多测试用例，提升泛化能力。
> 该方法可广泛应用于 OpenClaw、TraeCli 等 Agent 开发调试。

一个完整的 Skill 生命周期，除测试环节外，还包含外部工具集成、持续迭代测试、分发共享等模块。

## 与工具（MCP）衔接
Skill 通过指令编排完成 MCP 工具调用。指令需要明确：
1. 每一步调用目标工具；
2. 调用传入参数；
3. 定义工具预期输出。

## 错误与异常处理
健壮的 Skill 必须定义完备失败路径：
例如 API 调用失败场景，决策策略：重试、事务回滚，或是向用户索取补充信息。
所有异常分支逻辑，统一在 `SKILL.md`「故障排除」章节写明。

## 安全考量
### 保护措施
YAML 元数据禁止使用 XML 尖括号 `< >`，防范指令注入攻击。
### 权限控制
可在元数据通过 `allowed-tools` 字段限制 Skill 可调用工具范围，遵循**最小权限原则**。
