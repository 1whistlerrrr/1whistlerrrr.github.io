# 多渠道调研 — 详细指南

> 由主 SOP 步骤 3 按需加载。仅 🟡 中等和 🔴 复杂 Bug 执行本步骤。

## 检索渠道（按优先级自动降级）
| 优先级 | 渠道 | 适用场景 | 说明 |
|:---:|------|---------|------|
| 1 | **WebSearch** | 通用搜索引擎，覆盖博客、文档、社区问答 | 始终可用，作为首选入口 |
| 2 | **WebFetch** | 直接抓取特定页面（官方文档、Issue 页面） | 优先尝试；被墙/403/超时时自动跳过 |
| 3 | **本地知识库** | 项目已有文档、`memory/` 中的过往经验、CLAUDE.md | 不依赖外网，作为补充 |
| 4 | **代码库考古** | 同类问题在自身代码库中的历史处理方式 | `git log --grep` / `grep` 搜索历史修复 |

## 关键词构造
以「**异常类型 + 关键报错信息 + 技术栈/框架**」为核心：
- 框架/库相关：`[框架名] [异常名] [关键报错片段]`
- 语言/运行时相关：`[语言] [错误码/类型] [场景描述]`
- 通用模式：`[技术关键词] best practice [场景]`

## 降级流程
```
WebSearch 检索（优先级 1）
├── 找到相关链接 → WebFetch 抓取详情（优先级 2）
│        ├── 成功 → 提取关键信息
│        └── 失败（被墙/403/超时）→ 换 WebSearch 搜索缓存/摘要或替代来源
├── 结果不足 → 调整关键词重试（最多 2 轮）
│        └── 仍不足 → 降级到本地知识库（优先级 3）+ 代码库考古（优先级 4）
└── 无相关结果 → 标记"无业界参考"，基于代码分析独立判断
```

## 信息甄别
- **区分问题属性**：通用框架/依赖问题 vs 业务代码特有问题
- **方案可信度排序**：官方文档/Issue > 知名博客 > 社区问答 > 个人笔记
- **时效性**：优先采纳近 2 年内的方案，旧方案需验证 API/版本是否仍适用
- **关联评估**：借鉴方案是否与当前项目的版本、架构、约束条件匹配
