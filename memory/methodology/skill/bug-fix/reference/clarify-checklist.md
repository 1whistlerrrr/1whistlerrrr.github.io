# 需求澄清参考手册

## 🐛 Bug 修复专属问题清单
### 🔴 必问项
| 编号 | 问题 | 说明 |
|:---:|------|------|
| B-01 | **问题现象** | 具体表现是什么？报错信息、异常行为、不符合预期的输出？ |
| B-02 | **复现条件** | 什么操作、什么数据、什么环境下能复现？是必现还是偶现？ |
| B-03 | **期望行为** | 正确的情况应该是怎样的？ |

### 🟡 选问项
| 编号 | 问题 | 说明 |
|:---:|------|------|
| B-04 | **影响范围** | 是个别用户/数据还是全量影响？ |
| B-05 | **紧急程度** | 是否阻断主流程？需不需要紧急修复？ |
| B-06 | **环境差异** | 测试环境能复现吗？是否只在特定环境出现？ |
| B-07 | **最近变更** | 最近有没有相关代码/配置改动可能引入了这个问题？ |
| B-08 | **日志/截图** | 有没有相关的错误日志或截图？ |

## 追问话术规范
### ✅ 推荐方式
- "在开始之前，我需要确认几个关键信息：1. ... 2. ... 3. ..."
- "我已经理解了 [XXX部分]，但以下几点需要明确：..."
- "关于 XXX，我理解为 [你的推断]，如有偏差请纠正。另外还需确认：..."

### ❌ 不推荐方式
- ~~"请提供完整的需求文档"~~
- ~~一次列出 10 个以上问题~~
- ~~"你还有什么补充吗？"这类无实质内容的宽泛问题~~

### 标准追问模板
```markdown
在开始排查之前，我需要确认几个关键信息：
1. **问题现象**: 具体的报错信息或异常行为是什么？是否有错误日志？
2. **复现条件**: 通过什么操作、在什么数据/环境下能复现？是必现还是偶现？
3. **期望行为**: 正确的运行结果应该是怎样的？

> 💡 已理解的信息：[简要列出已从用户描述中获取的信息]

## 特殊场景处理
1. 用户明确说 "别问了直接做"
尊重意愿直接进入执行，在方案中标注所有基于假设的决策。
2. 用户需求已非常详尽
自检通过后无需强行追问，直接输出需求确认并进入执行。
