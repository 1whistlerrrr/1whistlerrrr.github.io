# Bug 定位分析输出模板
输出给用户确认，确认通过后方可进入修复阶段。

## Bug 定位分析
### 基本信息
- 复杂度等级: 🟢 简单 / 🟡 中等 / 🔴 复杂
- 处置建议: ✅ 修复 / 📋 观察 / ⏸️ 延期 / ❌ wont-fix
- 判定理由: [简述为什么这样判定]

### 问题现象
[复述用户描述的问题现象]

### 调研参考（🟡🔴 必填，🟢 可跳过）
- 搜索关键词: [使用的关键词组合]
- 渠道与结果:
  - WebSearch: [找到 N 条相关结果 / 无相关结果]
  - WebFetch: [成功抓取 X 个页面 / 全部失败，已降级]
  - 本地知识库: [有/无 相关记录]
- 业界参考: [同类问题的通用解法 / 框架已知坑点 / 官方 Issue 链接]
- 方案评估: [借鉴方案是否适用于当前项目]

### 根因分析
- 根因位置: [文件名:行号]
- 问题类型: [逻辑错误 / 数据问题 / 配置问题 / 并发问题 / 依赖问题 / 环境问题]
- 原因说明: [详细解释为什么会出现这个问题]
- 触发条件: [什么情况下会触发]

### 修复方案
- 修改文件: [列出需要修改的文件]
- 修改思路: [说明怎么改、为什么这样改]
- 影响评估: [修改是否可能影响其他功能]

### 是否需要同步修改
- [ ] 是否有其他模块存在相同问题
- [ ] 是否需要同步更新测试用例
- [ ] 是否需要更新文档/配置
