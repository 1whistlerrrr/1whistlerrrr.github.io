# 测试验证 — 详细指南

> 由主 SOP 步骤 7 按需加载。🔴 禁止跳过。

## 按复杂度分级测试
| 等级 | 最低测试要求 |
|:---:|-------------|
| 🟢 **简单** | ① 原复现步骤不再触发；② 肉眼检查修复代码逻辑正确 |
| 🟡 **中等** | ① 原复现步骤不再触发；② 手动验证关联功能的正常路径未被破坏；③ 检查 1~2 个边界条件 |
| 🔴 **复杂** | ① 原复现步骤不再触发（多种数据组合）；② 关联模块回归测试；③ 边界/异常输入覆盖；④ 如涉及并发，模拟并发场景验证线程安全；⑤ 评估是否需要补充自动化测试用例 |

## 测试用例构造
- **正向验证**：用原始 Bug 的复现步骤确认问题已消失
- **回归验证**：梳理修复代码的所有调用方，逐一确认核心路径功能正常
- **边界验证**：空值、极值、并发、超时等边缘场景
- **数据验证**（如涉及数据变更）：确认数据一致性、无脏数据残留

## 测试不通过的处理
```
测试结果？
├── ✅ 全部通过 → 进入步骤 8 自检校验
├── ⚠️ 原问题修复但引入回归 → 回退修复代码，重新评估方案
└── ❌ 原问题未修复 → 回到阶段一步骤 2，重新判定根因
```
