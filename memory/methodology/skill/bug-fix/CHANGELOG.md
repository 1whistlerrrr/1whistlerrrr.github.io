## 2026-07-30 (1) — 新增 Bug 分级分析、多渠道调研、测试验证

### 新增
- **Bug 分级与处置决策（步骤 2）**：增加复杂度分级（🟢简单/🟡中等/🔴复杂），根据等级走不同排查深度；增加处置决策树，判断是否值得修复；明确列出 wont-fix / defer 的四类场景及处置方式
- **多渠道调研（步骤 3）**：采用分层检索策略（WebSearch → WebFetch → 本地知识库 → 代码库考古），自动降级应对 GitHub 等站点无法直接访问的情况；增加关键词构造规范和降级流程图
- **测试验证（步骤 5）**：按复杂度分级测试（🟢快速验证 / 🟡标准验证 / 🔴全面验证），覆盖正向、回归、边界、数据四类测试；增加测试不通过的处置流程（回退 → 重新评估或重新定位）
- **分流出口**：简单 Bug 走快速路径（跳过调研，直接修复）；中等及以上走标准/完整流程；wont-fix/defer 场景输出判定理由后等待用户确认
- **交互 Header**：新增分析阶段、调研阶段、关闭/延期三种状态 Header

### 修改
- 原"阶段一：问题理解与定位"扩展为"阶段一：Bug 分析与分流"（4 个步骤）
- 定位模板增加复杂度等级、处置建议、调研参考（含渠道与降级记录）
- 自检清单增加测试验证维度（5 项），同步检查增加文档更新条目
- 阶段三步骤从 3 步扩展为 4 步（步骤 5-8）

### 设计意图
- 避免在简单问题上过度投入（一个空指针不需要全文检索 + 全面测试）
- 避免在复杂问题上投入不足（偶现并发问题需要深度排查 + 并发场景回归）
- 外网不可达时有明确的降级路径，不阻塞排查流程
- 修完必须验证——按 Bug 复杂度匹配测试深度，不跳过也不过度
