# 测试报告

将测试结果固化为**结构化、可追溯、可执行的测试报告**：用例执行情况、缺陷清单、覆盖率、风险与修复建议。

## 执行指令

1. **汇总执行结果** — 通过/失败/跳过/阻塞用例数
2. **分析缺陷** — 按严重等级划分：严重/高/中/低
3. **记录缺陷详情** — 复现步骤、影响范围、环境、截图/日志
4. **统计覆盖率** — 行/函数/分支覆盖率，标注盲区
5. **评估风险** — 遗留问题、未覆盖区域、发布风险
6. **给出建议** — 明确、可执行的修复方案，非模糊描述

## 使用示例

### 用户输入
"把这次回归的测试结果写成报告"

### 预期输出
```markdown
# 回归测试报告
- 用例：120 通过 / 3 失败 / 2 跳过 / 1 阻塞
- 覆盖率：行 82%，分支 65%（盲区：导出模块）

| 级别 | 缺陷 | 复现 | 建议 |
|------|------|------|------|
| 严重 | 导出 Excel 列错位 | 导出 500 条时 … | 修复排序逻辑，补单测 |
| 中 | 搜索无防抖 | 快速输入 → 多次请求 | 加 300ms 防抖 |
```
```

## 故障处理

| 场景 | 应对 |
|------|------|
| 缺陷描述含糊 | 强制补复现步骤 + 期望/实际对比 |
| 覆盖率盲区大 | 单独列出盲区清单并给补测方案 |
| 报告无人跟进 | 关联任务编号/负责人，形成闭环 |

## 做什么不做什么

### ✅ 做什么
- 结构化记录测试结果与缺陷，等级划分
- 提供可落地修复建议
- 留档供追溯、复盘、验收依据
- 关联需求/用例编号形成追溯链

### ❌ 不做什么
- 模糊描述缺陷（"页面有问题"），必须带复现步骤
- 隐藏或弱化失败用例
- 不划分严重等级，让修复无优先级
- 报告与代码/需求无关联，无法追溯
