# 单元测试

编写/审查单元测试，验证**单个函数或方法**的行为正确性。覆盖正向流程、异常分支、边界条件。

## 执行指令

1. **界定被测单元** — 确定要测的函数/方法及其职责
2. **识别并 Mock 依赖** — 外部依赖（DB、网络、其他服务）一律用虚拟替身
3. **设计用例** — 正向流程 + 异常分支 + 边界值（空输入、临界值）
4. **编写断言** — 校验明确预期结果，非仅判断真值
5. **运行 + 覆盖率** — 执行测试，检查覆盖率是否达标
6. **修复优化** — 失败用例定位根因（断言异常/环境问题/用例不稳定）

## 使用示例

### 用户输入
"给 calculateDiscount 写单元测试，高级会员 10% 折扣"

### 预期输出
```js
describe('calculateDiscount（计算折扣）', () => {
  it('高级会员享受10%折扣', () => {
    const result = calculateDiscount({ price: 100, userTier: 'premium' });
    expect(result).toBe(90);
  });
  it('传入负数价格时抛出异常', () => {
    expect(() => calculateDiscount({ price: -1, userTier: 'standard' }))
      .toThrow('价格不能为负数');
  });
});
```

## 故障处理

| 场景 | 应对 |
|------|------|
| 用例依赖数据库/网络 | Mock 掉依赖，绝不真实调用 |
| 单测时过时不过 | 排查执行顺序依赖、异步缺陷，隔离并修复 |
| 覆盖率不达标 | 针对未覆盖分支补用例，标注仍存在的盲区 |

## 做什么不做什么

### ✅ 做什么
- 测试纯逻辑、工具函数、Service 方法、状态转换
- Mock 外部依赖，隔离被测单元
- 统计覆盖率并针对盲区补用例
- 规范化用例命名（"应该 + 动作 + 条件"）

### ❌ 不做什么
- 调用真实接口、数据库（必须 Mock）
- 测试私有方法、内部实现细节
- 编写依赖执行顺序的用例
- 只测正常路径，忽略异常分支
