# 自动化测试框架

搭建并维护**自动化测试框架**，让测试可规模化落地：框架设计、环境基建、用例分层、稳定维护、团队能力建设。

## 执行指令

1. **选型** — 按技术栈与场景选框架（Vitest/Playwright/k6…）
2. **基建搭建** — 测试环境、测试数据、Mock 策略、CI 集成
3. **用例分层** — 按金字塔组织：底层单测多、顶层 E2E 少
4. **稳定性维护** — 识别不稳定用例，隔离并修复，禁止反复重试掩盖
5. **持续优化** — 按执行耗时/失败率/维护成本迭代
6. **团队赋能** — 沉淀模板与规范，降低编写门槛

## 使用示例

### 用户输入
"给前端搭一套可规模化的自动化测试框架"

### 预期输出
```markdown
## 选型
- 单测：Vitest + Testing Library（Vite 生态）
- E2E：Playwright（多浏览器）
## 基建
- 测试环境：jsdom + Mock Service Worker 拦截 API
- 数据：fixtures + 对象工厂
- CI：PR 时跑 单测+覆盖率；合并后跑 E2E
## 分层
- 单测 70% / 集成 20% / E2E 10%
## 稳定性
- 不稳定用例单独标记，2 天内修复或降级
## 赋能
- 沉淀页面/组件/工具 三类测试模板
```

## 故障处理

| 场景 | 应对 |
|------|------|
| 用例执行慢 | 并行化、分层（慢的放低频），控制全量时长 |
| 用例膨胀难维护 | 定期清理低价值用例，按 ROI 决策 |
| 框架过度设计 | 回退到最简可扩展结构，按需再加 |

## 做什么不做什么

### ✅ 做什么
- 设计可复用、可扩展的测试框架
- 搭建 CI 流水线自动执行与报告
- 用例分层，平衡速度与覆盖
- 建立用例维护机制，防止腐化

### ❌ 不做什么
- 什么都自动化（ROI 低的场景不必）
- 用例无限膨胀而无维护策略
- 过度设计框架，引入不必要复杂度
- 无视不稳定用例，靠重试掩盖问题
