# QA 方法论

规划与推进**整体质量策略**：质量定义、测试分层、左移介入、持续测试门禁，让人工与自动化测试形成合力。

## 执行指令

1. **定义质量标准** — 明确上线质量底线（覆盖率、缺陷上限、关键路径全通过）
2. **左移介入** — 在设计/需求阶段就考虑可测性与测试用例
3. **分层规划** — 单元/集成/E2E 各层职责与比例（金字塔模型）
4. **人工 + 自动化结合** — 自动化兜底回归，人工做探索性/体验测试
5. **建立持续门禁** — CI 接入质量检查，不达标不放行
6. **质量复盘** — 缺陷归因，反向改进流程

## 使用示例

### 用户输入
"给这个迭代制定质量策略"

### 预期输出
```markdown
## 质量目标
- 单测行覆盖率 ≥ 60%，关键模块 ≥ 80%
- 上线阻断：关键路径 E2E 全通过 + 无严重缺陷

## 分层策略
- 单元：业务 Service/工具函数（量多）
- 集成：核心 API 链路（Supertest）
- E2E：登录/主流程（量少）

## 左移动作
- 设计评审带上可测性清单
- 需求即用例，开发前先写关键用例

## 门禁
- CI：单测 + 集成 + 覆盖率，任一不达标阻塞合并
```

## 故障处理

| 场景 | 应对 |
|------|------|
| 团队抵触写测试 | 先立可执行标准 + 模板，降低门槛 |
| 门禁被频繁绕过 | 追根因：是用例脆弱还是标准过高 |
| 质量缺陷集中爆发 | 复盘归因，反向改进流程而非只加测试 |

## 做什么不做什么

### ✅ 做什么
- 制定质量策略与验收标准
- 推进左移测试（前置测试介入）
- 搭建持续测试与质量门禁
- 设计手工/探索性测试，补自动化盲区

### ❌ 不做什么
- 只看自动化覆盖率，忽视真实用户体验
- 全部押注自动化，放弃探索性测试
- 事后才测（右移），质量问题最后一刻才暴露
- 质量门禁形同虚设，放行未达标版本
