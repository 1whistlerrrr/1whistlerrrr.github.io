# 集成测试

验证**跨组件协作**的正确性——让模块与真实依赖（数据库、外部 API、消息队列）真正交互，确认"接缝处"没接错。单元测试测零件，集成测试测组装。

## 执行指令

1. **明确集成点** — 列出要验证的组件边界（API 端点、DB 读写、外部服务）
2. **准备真实依赖** — 测试数据库、测试环境 API、可回滚数据夹具
3. **编写跨组件用例** — 通过 HTTP/接口层发起调用，断言响应与数据落地
4. **执行测试** — 运行并观察真实协作行为
5. **验证一致性** — 检查数据状态、事务回滚、幂等性
6. **清理隔离** — 恢复测试数据，保证可重复执行

## 使用示例

### 用户输入
"用 Supertest 测用户注册接口，验证入库正确性"

### 预期输出
```js
const request = require('supertest');
await request(app)
  .post('/api/users/register')
  .send({ name: '张三', email: 'z@x.com' })
  .expect(200);
const saved = await db.findByEmail('z@x.com');
expect(saved.name).toBe('张三'); // 验证真实落库，非仅看响应码
```

## 故障处理

| 场景 | 应对 |
|------|------|
| 测试污染数据 | 用事务回滚或每个用例前清库，保证可重复 |
| 外部 API 不稳定 | 该集成点 Mock，仅保留目标链路真实 |
| 跨环境跑不过 | 隔离环境配置，禁止依赖本机特定状态 |

## 做什么不做什么

### ✅ 做什么
- 验证模块间契约与 API 接口正确性
- 数据库真实读写、事务一致性与回滚
- 外部系统对接（Supertest 测 HTTP API）
- 确认配置、中间件、序列化在真实链路下可用

### ❌ 不做什么
- 替代单元测试（细节验证仍属单测范畴）
- 使用生产数据（必须用测试夹具）
- 依赖本机特定环境而不做隔离
- 覆盖每条业务规则（粒度过大，交给单测）
